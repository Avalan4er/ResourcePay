# Test tooling (not shipped)

`package.json` exists only to hold the browser-automation harness as a **devDependency**: `playwright-core`, launched against the Chromium-family browser already on this machine (`msedge.exe`), so nothing is downloaded and the PWA itself stays dependency-free / build-step-free.

Run gates:
1. `node tests/test.mjs` — unit layer (all `src/app.js` exports + coverage manifest gate).
2. `python -m http.server 8123 --bind 127.0.0.1` then `node tests/e2e/run.mjs` — BDD acceptance layer in a real browser (`tests/e2e/*.feature`). Since 2026-10-25 the runner is split: `tests/e2e/run.mjs` (45-line orchestrator listing section order) + `harness.mjs` (launch/waits/geometry/thresholds) + six per-feature claim modules (`month-entry/settings-config/charts-toggle/history-export/persistence-reload/tap-and-toast .mjs`) sitting beside their `.feature` docs. One invocation, one persistent browser context; months are calendar-derived ONCE in `harness.mjs monthOptions()` (same rule as ui.js) and the 24-window is asserted from the live `<select>` in B1 — do NOT re-derive dates per module. A fresh-state pass needs the profile dir deleted first + no browser holding it; skipping that makes the precondition chk plus B3/B10 go RED on purpose (seeds/prices must be untouched), exit code 1 — never delete those checks to make a stale-profile run green.

Notes:
- The harness drives only stable `data-*` markers and asserts buttons via presence + JS-dispatched click; whole-tab re-render makes Playwright's actionability wait time out on stale nodes (that is a harness artifact, not a missing button).
- Picker branch (`window.showSaveFilePicker`) is Chromium-gated: the chooser click needs a real user gesture, so the runner only asserts the button exists — check filename/bytes by hand in Chrome.
- Test data stays local + disposable INSIDE the workspace: both the OPFS browser profile dir (`test-results/e2e-opfs-profile`) and screenshots live under `test-results/` (gitignored); `E2E_PROFILE` env still overrides if a different dir is wanted. Deleting the profile dir before a run makes that run prove boot-from-empty; leaving it lets the next run's `[DIAG] bootState` line show months survived a fresh browser launch.
- Killed harness runs leave headless `msedge.exe` children holding the profile lock → the next `launchPersistentContext` dies with "Target page, context or browser has been closed". Kill every `msedge.exe` first (`taskkill /F /IM msedge.exe /T`) and clear the profile dir before a clean-state run.
- Headless Edge never fires `requestAnimationFrame` reliably → any rAF-based settle probe hangs forever. Wait on repeated `page.evaluate` round-trips (rect stops changing) or on a structural marker instead; that is what `until()`/`frames()` in `run.mjs` now do.
- Cold-boot trap (2026-10-25, found while relocating the profile dir into `test-results/`): ui.js paints `#app` only after `bootLoad` awaits, so an INSTANT presence probe right after `goto` races a real empty-profile OPFS init and lauds a false absence (`FAIL target present: [data-tab=tabHistory]` on bootSurvival, 2/2 cold runs). `click()` now waits on presence via `until()` — a genuinely missing button still goes RED (that chk + `[wait-timeout]`).
- Unit-layer gotcha while fixing H2/B7: `tests/test.mjs` used to import `{ strict as eq } from 'node:assert'`, which binds node's **truthiness** assertion — every numeric comparison there was vacuous (`eq(1,2)` passed, `eq(0,0)` threw with message `0`). Re-pinned 2026-10-25 to `{ strictEqual as eq } from 'node:assert/strict'`; keep that import. Zero-valued and boolean expectations are now asserted through `ok(x === …)` where the message must stay readable (e.g. `clearHistory`, garbage money).
- Acceptance-harness rule that bit bug batch 2: markers are per-tab, so reading `.cfgNew`, `.chart` or History rows requires `tab(…)` first — a check aimed at another tab's card returns null and launders nothing (it stays RED, but the RED was the harness, not the app). Ledger records those separately in tasks/bugs-2.md.
- iPhone-only behaviors that the desktop harness cannot prove stay manual: Safari ignores `<a download>`; iOS tap/zoom gestures (batch-2 `shrink-to-fit=no` + batch-3 scale lock `minimum-scale=1,maximum-scale=1` and `touch-action:none` on every control in `src/index.html`/`src/style.css`, verified only as computed meta + computed `touchAction` + full-size tap targets — see tasks/bugs-2.md G2 / tasks/bugs-3.md Z1); batch-5 U1's real scroll reachability (the `U1` claim proves the clearance RULE on `#app`; whether iPhone Safari's scroll container honors it in every chrome mode stays a manual read). What IS locally reproducible: native-control painting and stacking — Z2 asserts computed `appearance:none`/transparent radio + side-by-side pill rects, so a WebKit paint or flex regression goes RED on desktop instead of silently.
- Batch-5 debugging trap worth remembering: a harness click that passes the hit-test yet changes nothing in the app usually means the element's handler was never bound — an edit had swallowed `ab.onclick = ...` into the tail of a `//` comment (valid JS, silent, every geometry check green). Temp `H.diag()` lines inside `click()`/`clickAndSave()` — flushed only on RED runs — pinned it in two diagnostic passes; remove such temp diags when the case closes.
- Bug batch 4 (`tests/e2e/ui-polish.mjs`, ids P1–P7 in tasks/bugs-4.md) is entirely locally provable: every claim reads computed styles/geometry (pill/column flow/pill-fill/stretch), so no manual-iPhone caveat applies there. Its thresholds live ONCE in harness (`BTN_W_MAX` next to the other single-source bounds) and its sections must run BEFORE `settings-config: wipeSavedMonths`, which erases the months P7 reads.

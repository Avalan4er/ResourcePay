## Toast / viewport
- [x] **G1** Saved toast sits under all other elements and is red; it should read as a success (green) and paint above content. e2e `G1`: after Save the toast carries `data-kind=ok`, its computed position is `fixed` with z-index 9, its background equals the app's own `--ok` token, and a rejected save keeps `kind=err` on `--warn`. Real root cause: style.css `.banner` was `position:absolute` with no z-index (later siblings paint over it) plus one red background for every copy — success vs error was never distinguished in the DOM. Fix: ui.js `toast()` stamps the kind, style.css lifts and colours by kind.
- [x] **G2** Tapping an input field zooms the page in too much; it should not zoom. e2e `G2`: the viewport meta declares `width=device-width` AND switches iOS auto-fit off (`shrink-to-fit=no`), and every visible Bills control paints as a full tap target (≥ 40 CSS px both ways). Honest limit recorded here: Safari's shrink-to-fit re-zoom cannot be reproduced from desktop Edge, so the iPhone tap itself stays a manual-verify item (same kind of caveat as the CSV picker note in `tasks/test-deps.md`).
- [x] **G3** Toast is invisible after the page is scrolled down (it belonged to the top of the document, not the screen). e2e `G3`: scrolling the Charts tab yields `scrollY > 0` (the page really overflows one phone screen) and the banner rect is still inside the viewport. Same CSS rule as G1 pins it (`position:fixed`, bottom inset-safe) with `pointer-events:none` so it can never swallow a tap on Save.

## Bills tab — garbage resource
- [x] **G5** Garbage row always prints "no baseline yet". A fixed monthly-cost row has no odometer baseline, so that copy is pure noise. e2e `G5`: the trash Bills row carries no `i.prev` element at all (meters still carry theirs). Real root cause: `build` painted it via `fieldRow` while `refreshPreviews` already skipped fixed rows — the two paths disagreed. Fix: ui.js `fieldRow` omits the prev node for fixed rows.
- [x] **G6** Garbage has no unit — the typed value is absolute monthly ₽ and may differ per month. Unit case `G6a`: `describeCharts(...,'money')` garbage bar equals the entered 310,50 even when that meter's config price is 2 (today it multiplied), and a live preview of another month equals its own entered amount. e2e `G6b`: the trash row is labelled with STR's monthly-cost copy and carries no ₽/unit multiplier input. e2e `G6c` (same rule in Settings): the garbage config row carries no multiplier input and prints no price figure in its header, while all four meter rows keep their editable ₽/unit field. Fix: app.js `rowMoneyOf` returns `curr` for fixed rows; ui.js drops the price control + `@ price` fragment on fixed rows and labels the remaining one.
- [x] **G7** Settings has no way to clear saved months (user-requested task). e2e `G7`: first tap on the new button paints STR's confirm copy and writes nothing (`rpSaved` unchanged), a History visit still shows every month, leaving Settings disarms the pending wipe so the next single tap only re-arms, the second consecutive tap empties History, and the empty state survives a hard reload while all config rows (incl. the added Boiler meter) stay. Fix: new pure export `clearHistory` (+ its unit case: history emptied, config untouched, cleared CSV = marker+header only) + ui.js two-tap glue with the disarm-on-tab-switch guard.

## Charts tab — mode control
- [x] **G4** The "by money / by volume" control paints as a single round knob; it should read like an iOS switch. e2e `G4a`: the toggle card carries two radio knobs with exactly one checked; `G4b`: each knob sits right under its own STR mode label; the size check shows both knobs paint as full pill tracks (≥ 40 px), tapping the checked knob changes nothing, and tapping the other flips every chart back to volume bars. Two real causes: only one radio existed (so one state was ever visible), and the knobs carried no `data-for` attribute so the CSS track styling matched nothing (bare native dot). Fix: ui.js emits a label+knob pair per mode with `data-for` on both; style.css draws the pill tracks.

## Settings tab — add-new-meter card
- [x] **G8** In the add-new-meter card all four labels stack before all four inputs. e2e `G8`: reading `.cfgNew` children in order, each field's label is its input's immediate predecessor and all four labels carry STR copy. Fix: ui.js appends label+input pairs (the pairing rule `fieldRow` already used).
- [x] **G9** The add-new-meter card header reads "enter the latest known reading of this meter" — misleading; it should name the card. e2e `G9`: the card's first painted text equals STR's add-meter title, while the seed-required sentence stays visible later in the card as a field hint. Fix: ui.js header node from new STR key `addMeterTitle`, hint moved to an `i.tag` after the fields.

## P1 — chart headers print at the left of the chart
- [x] **P1** A chart card prints its name beside the bars instead of on top. Root cause is layout, not paint: `.chart{display:flex;align-items:end}` made the `<h4>` a flex item **in the bar row**, so it got bar-sized width and landed at the left edge. e2e `P1`: every chart card computes column flow and its header's bottom sits over the tallest bar (plus a non-vacuity row demanding real bars). Fix: applyCharts puts the bars in their own `.bars` row (same lever as Z2's `.swRow`) and style.css makes `.chart{flex-direction:column}` with the header line first.

## P2 — chart labels read as micro-text inside the bars, no key
- [x] **P2** The month/value caption was rotated `writing-mode:vertical-rl` micro-type painted **inside** the colour pill, and nothing explained which bar meant which month. e2e `P2`: no child of a bar falls inside its pill rect; every month gets a horizontal axis caption under its bar (short `YY-MM`, so it fits a 42px slot); every card with bars carries one horizontal legend naming each month and its value. Fix: applyCharts emits `<b class="m">` under the baseline + one `<small class="legend">` per card; bars keep `data-month`/`data-v`, so the charts-toggle claims (money sums, `.neg` flags) stay meaningful.

## P3 — "final calculations string is dashed"
- [x] **P3** The Δ/ruble preview line reads as if struck through. Stated symptom ≠ cause: ui.js built the preview in an HTML `<s>` element, which IS strikethrough semantics ⇒ `text-decoration:line-through` painted across the numbers. e2e `P3`: every painted `[data-role=pv]` line computes `textDecorationLine === none`. Fix: a neutral block (`<p class="pv">`) plus the style.css selectors re-pointed to it; the marker stays `data-role=pv`, so the B3/B10 preview probes keep their meaning.

## P4 — "₽ per unit" row shows no price
- [x] **P4** The Bills price row is a bare caption (`STR.lblPrice`) with no figure — because B8 hid the prefilled input *and its label* while it equalled the default, so the price actually used was invisible. e2e `P4`: each meter row's price line states the effective number inside the STR template `{x} per {unit}` (number matches that row's default/edit and the unit is named) and stays painted at default; unit case demands the new key exists in `STR`. Fix: STR gains `lblPriceOf: '{x} per {unit}'` (placeholders keep it hand-translatable), `describeMonthForm` exposes which figure the money used, and `syncPrice` writes that readout — only the INPUT hides, so B8's tap rule survives.

## P5 — card inside a card
- [x] **P5** Bills rows and Settings rows paint their own rounded, shadowed panels inside the tab's card, so the page reads as cards nested in a card. e2e `P5`: `.field`, every `[data-id]` row and `.cfgNew` compute a transparent background with no box-shadow, while full-width rhythm (≥4px gaps) survives. Fix is style.css only — flat blocks (hairline left rule keeps each row grouped to its controls); chart cards keep their own frames because those are chart panels, not nesting.

## P6 — the CSV button is huge
- [x] **P6** The History export pill spans the whole phone width (~310px). Root cause: `.card` is `display:flex;flex-direction:column`, so children stretch on the cross axis ⇒ every card button (export/save/apply/clear) became full-bleed. e2e `P6`: `[data-el=exportBtn]` and Apply/Clear hug their copy (≤ `BTN_W_MAX`, one harness threshold) and stay ≥40px tall tap targets. Fix: `.card button{align-self:center}` — the copy stays in STR and the comfortable-tap floor stays untouched.

## P7 — the History item is not human readable
- [x] **P7** Each saved month printed as one run-on dashed sentence; the user asked for a small section with a table (meter name | reading | Δ reading | ₽ per unit). Two halves: `describeHistoryRows` parts gained that month's own stored `curr` and its effective `price` (unit case asserts both, still self-contained per month so CSV/backup rules are unaffected), and ui.js renders `<div class="row" data-month data-total>` = heading line + a real `<table class="mtbl">` whose four STR headings (`colMeter/colReading/colDelta/colPrice`) mark their columns with `data-col`, one row per meter, then the month-total line under it. e2e `P7`: table shape, column roles, one row per meter, readable total line, raw `data-total`. Callers follow: harness `snap().rows` carries the raw total and `history-export.mjs`'s money-agreement claim reads that attribute (with a finiteness guard) instead of splitting prose on an em dash — the new structure makes prose parsing unsafe, so the claim had to move with the DOM.

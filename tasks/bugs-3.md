## Z1 — tapping an input field zooms the page in
- [x] **Z1** Tapping an entry/settings field re-zooms the iPhone page; it should not zoom at all (the user then asked to make the whole page behave like an app: no zooming anywhere). e2e `Z1a`: the viewport meta pins the scale BOTH ways (`initial-scale=1,minimum-scale=1,maximum-scale=1`) so a pinch has nothing to do; e2e `Z1b`: every painted input/button/select carries computed `touch-action:none`, which per MDN also kills iOS double-tap-to-zoom — meta caps alone never did that. Root cause: batch 2 only declared `shrink-to-fit=no` (G2); iOS keeps its own smart-pinch/double-tap zoom on tap regions, and ignores scale intent when it re-fits. Honest tradeoff recorded in SPEC/README: pinch-zoom is off page-wide, so WCAG 1.4.4 "zoom" is served by the app's own type scale + OS accessibility zoom instead — this is what the user asked for ("behave like an app"). The real iPhone gesture itself remains manual-verify (same caveat class as the CSV picker / G2): the desktop harness proves the levers are painted, not Safari's gesture.

## Z2 — Charts "by volume / by money" control
- [x] **Z2** The mode control renders one label+knob *below the other* and still looks like a native radio dot on iPhone; it should read as one iOS-style switch row with both states visible. Two real causes (both reproducible locally, unlike Z1): `.card` is `display:flex;flex-direction:column`, so the label+radio pairs stacked vertically instead of sitting side by side in one row; and nothing reset `-webkit-appearance`, so WebKit keeps painting its native radio control despite our width/border/background (`accent-color` only tints it). e2e `Z2a`: the two pill tracks sit on ONE row (same y-line + a real horizontal gap) and each painted rect is a full tap target; e2e `Z2b`: computed style of both radios has `appearance:none` with a transparent background — no native control may paint, every pixel comes from our CSS; e2e `Z2c`: exactly one mode is selected and its own knob carries the app green (`--ok`) while the other keeps a neutral painted fill, so which state is on is readable without tapping. Fix: ui.js emits one `<span class="modeSw">` per mode (its STR label + an invisible full-track radio + a CSS-drawn `i.knob`) inside a `.swRow` flex row; style.css draws the pill/dot and `-webkit-appearance:none`s the radio — `data-el=modeToggle` stays a real radio so C2 keeps its meaning.
